## Part A — Supabase project

### A.1 Project decisions

- **Topology:** XIX, MMM and OM share one Supabase project (decided). XIX tables live in schema `xix`; MMM's remain where they are. Cross-app reads (Where to now) are views in Doc 3.
- **Auth:** Supabase Auth with **anonymous sign-in enabled**. Every XIX user starts anonymous; linking (email OTP or Sign in with Apple) upgrades the same `auth.users.id`, so nothing migrates. `profiles.is_anonymous` mirrors `auth.users.is_anonymous`.
- **Migrations:** `supabase/migrations/` in the repo, applied with the Supabase CLI; never edited in the dashboard. One migration per concern below.
- **Naming:** snake_case, singular schema `xix`, plural tables. All timestamps `timestamptz`. All ids `uuid default gen_random_uuid()`.

### A.2 Migrations (in order)

1. `0001_profiles_courses.sql` — `xix.profiles`, `xix.courses`, `xix.course_holes` per Doc 1 A.2. Trigger on `auth.users` insert → create profile.
2. `0002_rounds_players.sql` — `xix.rounds`, `xix.players`. `rounds.join_code` generated by `xix.gen_join_code()` (6 chars, unambiguous alphabet, unique).
3. `0003_scores.sql` — `xix.scores` with `updated_at` maintained by trigger.
4. `0004_games.sql` — `xix.games`, `xix.game_players`.
5. `0005_callouts.sql` — `xix.callouts`, `xix.callout_responses` (per Doc 1 v1.2: no `responder_id`; responses table).
6. `0006_stickers.sql` — `xix.stickers` with `sender_player_id NOT NULL`.
7. `0007_results_medals.sql` — `xix.results`, `xix.medals`, `xix.confirmations`.
8. `0008_crews_rankings.sql` — `xix.crews`, `xix.crew_members`, `xix.ranking_entries`.
9. `0009_rls.sql` — enable RLS on every table; policies in A.3.
10. `0010_rpc.sql` — functions in A.4.
11. `0011_triggers.sql` — triggers in A.5.
12. `0012_indexes.sql` — indexes in A.6.

### A.3 RLS policies

Helper: `xix.is_round_member(round_id)` = exists `players` row with `profile_id = auth.uid()` and `left_at is null`, OR `rounds.owner_id = auth.uid()`. `xix.is_round_owner(round_id)`. `xix.my_player_id(round_id)`.

| Table | select | insert | update | delete |
|---|---|---|---|---|
| profiles | own, or any profile that shares a round/crew with you (name only via view `xix.public_profiles`) | trigger only | own | — |
| courses / course_holes | authenticated | authenticated | `created_by = auth.uid()` | — |
| rounds | member; or by `join_code` via RPC only | authenticated (owner = auth.uid()) | owner | owner, only while `status='setup'` |
| players | member | owner | owner (any field); member (own row: `display_name` only) | owner, only unclaimed rows |
| scores | member | own row, or owner | own row, or owner | — |
| games / game_players | member | owner via RPC `set_games` | owner via RPC | owner via RPC |
| callouts | member | member (caller = own player) via RPC `create_callout` | — | — |
| callout_responses | member | own player, must be in `target_ids`, via RPC `respond_callout` | — | — |
| stickers | member | own player as sender, via RPC `send_sticker` | target only, `played_at` | — |
| results | member | service role | service role | — |
| medals | own | service role | — | — |
| confirmations | member | own, one per round | — | — |
| crews / crew_members | member | authenticated / crew owner | owner | owner |
| ranking_entries | authenticated | service role | service role | — |

No policy anywhere references money, stakes or settlement. Keep it that way in review.

### A.4 RPCs (SECURITY DEFINER, all validate membership)

- `xix.join_round(code text) → rounds` — returns the round for a join code (status `setup` or `live`), without requiring membership. Does not add the caller; the client then calls `claim_row`.
- `xix.claim_row(round_id, player_id)` — sets `profile_id = auth.uid()`, `claimed_at = now()` iff the row is unclaimed and the caller is not already in the round.
- `xix.add_guest(round_id, display_name) → players` — owner only; new unclaimed row at the next seat.
- `xix.set_games(round_id, games jsonb)` — owner only; allowed while no score exists on hole 1; replaces `games` and `game_players` transactionally.
- `xix.enter_score(round_id, player_id, hole, strokes int?, picked_up bool, client_ts timestamptz)` — upsert with last-write-wins on `client_ts` (the client's monotonic timestamp), validates own-row-or-owner, returns the row.
- `xix.create_callout(round_id, hole, kind, target_ids uuid[], params jsonb)` — caller must be a member; rejects if any participant already has a score on the hole; caller stripped from targets.
- `xix.respond_callout(callout_id, action)` — caller's player must be in `target_ids`; rejects if the hole is closed (any participant score) or a response exists.
- `xix.send_sticker(round_id, hole, target_player_id, sticker_key, pack_key)` — sender = caller's player; enforces the cap (3 per hole per sender); enforces pack entitlement.
- `xix.end_round(round_id)` — owner only; sets `status='ended'`, `ended_at`; enqueues engine run.
- `xix.leave_round(round_id)` — sets own `left_at`.
- `xix.confirm_round(round_id, action)` — insert into `confirmations`.

### A.5 Triggers

- `profiles_from_auth` — on `auth.users` insert.
- `scores_touch_updated_at`.
- `callouts_close_on_score` — after insert/update on `scores`: for callouts on that hole where the scoring player is caller or target, mark `closed_at` (new column on `callouts`) so `respond_callout` rejects further responses.
- `stickers_rate_limit` — before insert: reject the 4th per (round, hole, sender).
- `enqueue_engine` — after insert/update on `scores`, `games`, `game_players`, `callouts`, `callout_responses`: `pg_notify('xix_engine', round_id)` and insert into `xix.engine_queue(round_id, requested_at)` (dedup by round).
- `auto_confirm` — `pg_cron` nightly: rounds `ended_at < now() − 48h` with no objection → mark `counted_at`.

### A.6 Indexes

`scores(round_id, hole)`, `players(round_id, profile_id)`, `players(profile_id)`, `callouts(round_id, hole)`, `stickers(round_id, hole)`, `medals(profile_id, created_at desc)`, `rounds(join_code)`, `engine_queue(round_id)` unique.

## Part B — Engine runtime on the server

### B.1 Decision

The authoritative engine run is a **Supabase Edge Function (`xix-engine`) calling the XIXScoring package compiled to WebAssembly** via SwiftWasm. Rationale: one codebase, the 24 fixtures verify the Wasm build exactly as the native one, no TypeScript port to keep in step. Fallback if the Wasm toolchain proves brittle in the first week: a small Deno TS port of only the *contract and dispatch*, calling native Swift on a Fly.io worker — still one scoring implementation.

### B.2 Flow

1. Trigger enqueues `round_id`.
2. `xix-engine` (invoked by a Database Webhook on `engine_queue` insert) loads `RoundInput` via a single RPC `xix.round_input(round_id)` that returns the JSON shape the engine decodes (same shape as the fixtures — reuse the fixture decoder).
3. Runs the engine; writes `results(round_id, version, payload)`; on `status = complete` and `rounds.status = 'ended'`, upserts `medals` idempotently by `(profile_id, round_id, key)` and updates `profiles.level_auto` (rolling average vs par over the last 10 complete rounds with par).
4. Deletes the queue row. Errors leave the row for retry (max 5, then dead-letter table).

### B.3 Client parity

The iOS app runs the same package locally on every score change for instant UI. The server result replaces the local one when it arrives (same `engineVersion` → identical; the client asserts equality in debug builds and logs a mismatch as a bug).

## Part C — iOS data layer

### C.1 Structure (Swift packages in the repo)

- `XIXScoring` — done.
- `XIXModels` — Codable types mirroring the tables; generated from the migrations with `supabase gen types` then hand-wrapped.
- `XIXData` — Supabase client, repositories, Realtime, offline queue, auth. No UI imports.
- `XIXUI` — SwiftUI views, design tokens, renderers.
- App target `XIX` — composition only.

### C.2 Round session

`RoundSession` (actor) is the single source of truth for a live round on device:

- Holds `RoundInput` (built from local tables) and the latest `RoundResult` (local engine), plus `stickers`, `callouts` with responses, `players`.
- Subscribes to one Realtime channel per round: `xix:round:{round_id}`, Postgres changes on `scores`, `players`, `callouts`, `callout_responses`, `stickers`, `games`, `game_players`, `results` filtered by `round_id`. Presence is enabled so the hole card can show who's on the card (no UI in V1 beyond a dot).
- Applies incoming rows with **last-write-wins per cell** keyed on `updated_at`/`client_ts`; emits a `MergeNotice` ("Dave changed hole 6") when an incoming score replaces a locally *displayed* value for a row that isn't the user's own.
- Re-runs the local engine on every applied change (debounced 150 ms).

### C.3 Offline queue

- Every mutation is written to a local SQLite store first (`GRDB`), with a `client_ts` from a monotonic clock, then queued as an RPC call.
- Queue drains FIFO when connectivity returns; each call is idempotent (score upsert keyed by primary key + `client_ts`; sticker/callout inserts carry a client-generated `id`).
- Conflict resolution on drain is the same LWW rule; if the server rejects (RLS, cap, closed callout), the local row is reverted and a one-line notice is shown.
- The grid and hole card always render from the local store; network state never blocks entry.

### C.4 Auth

- First launch: `signInAnonymously()`. Profile created by trigger. Display name asked only when the user creates or joins a round.
- Linking: Settings → "Keep my account" → email OTP or Sign in with Apple → `linkIdentity`. Same `auth.users.id`; no data moves.
- Join by link: universal link `xix.golf/r/{code}` → app calls `join_round(code)` → shows the claimable rows → `claim_row`. Web fallback page for no-app is a static page (Doc 3).
- Result-link confirm: results screen from a link → `confirm_round(round_id, 'confirm')` also performs `claim_row` if the user's row is still unclaimed.

### C.5 Course data

- `courses` created inline from setup; `course_holes` optional. OSM enrichment is a background job (Doc 3). No blocking on course data anywhere.

## Part D — The first two screens on real data

### D.1 Design tokens (`XIXUI/Tokens`)

- Colours: `xixGreen` (header), `xixSheet` (white), `xixCream` (sticker ground), `xixInk` (green line), `xixAccent` (orange, used only where Pass 5 uses it: LIVE, the in-play accent line, streaks). MMM yellow is not a token in XIXUI; it lives only in the MMM handoff component (Doc 3).
- Type: SF Pro; tracked caps style; number style with tabular figures, right-aligned.
- Spacing and radii per the Pass 5 file (cards radius 24, 3px gaps, 44pt minimum controls).

### D.2 Shared renderer

`ScorecardRenderer` produces the grid as a SwiftUI view **and** as an image (via `ImageRenderer`) from the same view tree; parameters: players, scores, par, marks, stickers (with sender chips), live callout mark, names-or-initials, width (screen or 322pt chat width). Used by the grid screen, the export, the results screen and the medal context card. Build this once, first.

### D.3 Grid (Layer 1)

- Header: leaderboard strip with mode pills (active game default; Gross toggle). Rows from `RoundResult.leaderboard`.
- Two nine-hole blocks; per-cell marks from `perPlayer.marks`; stickers at 24–28pt anchored top-right, one per cell with `×n` tab; totals columns never carry stickers; live callout mark on the column header.
- Tap cell or hole number → hole card. "Play hole N" → hole card on the current hole (first hole with any empty score).

### D.4 Hole card (Layer 2)

- Header: hole, par, yards/stroke index when present; in-play strip from the games that include this hole (Skins carry, Nassau segment, Stableford).
- Rows: avatar chip, name, game standing from `GameResult.display`, score box.
- Score entry: tap own row (or any row as owner) → number pad panel (1–9, 10+, Picked up, par key largest, Clear/Save) → `enter_score`. Saving the last score on the hole closes the pad and triggers the nudge if the engine reports a hole event or a blow-up.
- Callout banner: the CALLED OUT die-cut on white with SIGN IT / DUCK IT hit areas → `respond_callout`. Per-target state shown as small chips on the banner edge (signed / ducked / pending).
- Stickers: pinned at 60–72pt on the score side; sender chip; long-press lifts. Tray as a panel (Doc 3 wires Rive; here stickers render as static PNGs from the bundle).
- Ink event line under the rows from `holeEvents` for this hole.
- Swipe between holes; hole strip at the bottom.

### D.5 Acceptance for this document

- Two devices on the same round see each other's scores within 1 s on Wi-Fi.
- Airplane mode on one device for three holes, then reconnect: all scores present on both, correct LWW, one merge notice per replaced displayed cell.
- Server `results.payload` equals the local `RoundResult` for the Fraserview round entered by hand on device.
- Guest join via link → claim row → score own row; owner can still edit it.
- Anonymous account linked to email → same rounds and medals visible.
